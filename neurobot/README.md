# neurobot — непрерывная и безопасная работа робота NeuroChip

Робот лаборатории NeuroChip — колёсная база на STM32, Jetson Nano, лидар URG-04LX, камера RealSense D435i, ROS 2 Foxy — реагирует на жесты: распознавание лаборатории (YOLOv5 → траектория → SNN) выбирает манёвр. Сверху работает агент PicoClaw, который обращается к роботу через MCP. Эта часть проекта делает так, чтобы стек робота работал непрерывно и безопасно: поднимался одной командой и в правильном порядке, сам восстанавливался после сбоев, не ехал без свежей команды, останавливался перед препятствием и честно сообщал агенту и оператору, что происходит.

## Основные решения

- **Жест → манёвр без LLM в контуре.** Реакция на жест замыкается на роботе в графе ROS 2, без LLM, MCP и rosbridge: на жест — 0 обращений к модели. Агент работает уровнем выше, командами уровня задачи, и сырых скоростей не получает.
- **Один писатель `/cmd_vel` — `safety_gate`.** Исполнитель выбирает между жестом и агентом и пишет желаемую скорость в `/neurobot/cmd_vel_req`. `safety_gate` по лидару, камере глубины и IMU пропускает её, урезает или обнуляет и только после этого пишет в `/cmd_vel`. При сомнении робот стоит. На старте, при выходе и при отказах в `/cmd_vel` уходит явный ноль. Аварийную защёлку может поставить кто угодно, а снять — только человек через `sudo`.
- **Юниты systemd с готовностью и сторожем.** Компоненты запускаются по готовности, а не по `sleep`: `Type=notify` с READY и WATCHDOG, пробы готовности, проверки перед стартом. `neurobot doctor` называет первый отказавший компонент и причину. Если умер узел драйвера или rosbridge внутри `ros2 launch`, юнит гаснет, и systemd поднимает его заново. Зависший узел находит сторож по свежести тем.
- **MCP для агента.** Команды агента идут через исполнитель и `safety_gate`. rosbridge слушает только 127.0.0.1 и пропускает только темы и сервисы из списков разрешённого. `robot_get_status` отдаёт состояние `safety_gate`. `robot_nudge` возвращает фактический исход (`ok`, `blocked`, `estop` или `unconfirmed`), а не «отправлено». `robot_stop` сразу даёт ноль через `/neurobot/stop_now`. MCP-сервер — `ros_mcp_server` лаборатории с нашим патчем. Патч в репозиторий не входит, здесь лежат конфиг, проверки агентского пути и замеры.
- **Пульт оператора — «окно, а не руль».** Пульт проигрывает записанные прогоны или показывает живое состояние робота. Команд у него две: «СТОП движения» и «Поставить защёлку».

```
жесты: perception ─► /cmd_vel_gesture ──────────────┐
агент: MCP ─► rosbridge (127.0.0.1) ─► /cmd_vel_agent ┴► исполнитель ─► /neurobot/cmd_vel_req
  ─► safety_gate (единственный писатель /cmd_vel) ─► twist_mux ─► diff_drive_controller ─► база
стоп агента и пульта: /neurobot/stop_now ─► safety_gate (ноль сразу)
```

Готовые компоненты, а не наша разработка: ROS 2, Gazebo, twist_mux, ros2_control, rosbridge, systemd, PicoClaw, MCP SDK.

## Что проверено на цифровом двойнике

Все проверки шли в ВМ Lima (Ubuntu 24.04, ROS 2 Jazzy, Gazebo Harmonic с программным рендерингом) с заглушкой LLM `bench/mockllm`. Числа — ориентир стенда, а не результат на роботе.

- **Безопасность.** На итоговом коде в сценариях со стеной, низким ящиком, человеком на пути, столбом в слепом секторе и поворотом у стула касаний 0. С края площадки робот не упал, на склоне и при ударе срабатывает защёлка.
- **Стоп агента.** После `robot_stop` через MCP ноль в `/cmd_vel` приходит через 1,9 / 2,7 мс (p50 / p95). Все 30 замеров уложились в 100 мс, и после стопа робот ни разу не поехал.
- **Стоп из пульта.** Ноль в `/cmd_vel` приходит через 2,0 мс (p95) от запроса, 30 из 30.
- **Восстановление.** После `kill -9` узла лидара, камеры или rosbridge стек снова работает через 1,7–2,8 с, после зависания (SIGSTOP) — через 4,5–4,9 с, без участия человека. На «сломанных» стартах doctor называл именно внесённую причину.
- **Ответы агента о движении.** 0 ложных ответов из 20: ответы сверялись со сдвигом по `/odom`.

Двойник не моделирует STM32 и UART, проскальзывание шин и реальный шум RealSense. Распознавание жестов на нём не проверяется: формы жестов синтетические, а детектор руки подставной.

## Что не проверено на реальном роботе

На роботе ничего не запускалось. Код для него (ROS 2 Foxy, Python 3.8) проверен под Python 3.8 тестами логики и `py_compile`. Обёртка `ros2 launch` проверена против launch 0.10.10 из Foxy, юниты — статически против директив systemd 245. Не проверялись Foxy целиком (rclpy, rosbridge 1.3.1, launch_ros), Jetson Nano, настоящие лидар, камера и база. Бюджет 4 ГБ — это модель и замер в cgroup ВМ, а не замер на плате. Итоговые цифры может дать только проверка на самом роботе.

## Что не входит в репозиторий

Код лаборатории NeuroChip в репозиторий не входит: YOLO и SNN с весами, `predict_live.py`, MCP-серверы `ros_mcp_server.py` и `robot_vision_mcp_proxy.py`, исходники робота. Наши патчи к этому коду тоже не входят, как и артефакты прогонов (`experiments/results/…`). Тесты, которым нужны эти файлы, пропускаются с указанием причины. Тесты с ROS 2, Gazebo или PyTorch вне ВМ тоже пропускаются.

## Запуск

```bash
.venv/bin/python -m pytest -q -p no:cacheprovider neurobot
.venv/bin/python -m neurobot.ui serve --bundle neurobot/ui/samples/demo_hall.json.gz   # http://127.0.0.1:18120/
```

Для двойника и наборов нужен Linux с ROS 2 Jazzy и Gazebo Harmonic. На Mac они работают в ВМ Lima ([docs/robot_sim.md](../docs/robot_sim.md), `scripts/sim`).

Отдельный MCP-адаптер робота на Go ([robotmcp](../robotmcp/README.md)) сделан для TurtleBot3 с Nav2. Для робота NeuroChip агентский путь по умолчанию идёт через MCP-сервер лаборатории с патчем.
